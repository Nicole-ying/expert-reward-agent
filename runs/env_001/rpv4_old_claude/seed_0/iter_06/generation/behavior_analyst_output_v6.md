# 训练行为诊断报告

## 1. 当前策略行为画像
Agent 学会了持续接近目标（goal_approach_progress 每步均值 0.097，100% 激活），但不会稳定着陆——仅 3/20 回合终止，平均耗尽 951.8 步后被截断，得分 -38.36。

## 2. 组件健康度
- **goal_approach_progress**: 主导但错位（系数 80.0 过高，淹没了其他信号）
- **velocity_brake_near_target**: 淹没（每步 -0.033 量级，被 progress 的 +0.097 压制）
- **orientation_stability**: 淹没（每步 -0.005 量级，几乎无影响）
- **contact_landing_reward**: 死组件（仅 0.3% 激活率，episode_sum 9.55 vs progress 92.03，量级差 10 倍）

**演进分析**：iter 5 将 goal_approach_progress 系数从 10.0 暴涨至 80.0，导致：
1. goal_ep_sum 从 23.59 → 92.03（+290%），淹没所有其他信号
2. contact_active_rate 从 50.5% → 0.3%（崩溃），因 agent 不再需要接触就能获得高奖励
3. terminated 从 13/20 → 3/20（-77%），agent 学会"永远接近但不着陆"以最大化累积 progress 奖励
4. len 从 737.0 → 951.8（+29%），验证了"拖延着陆"策略

**交互效应**：过度放大 progress 信号导致 contact 组件完全失效（激活率降至 0.3%），同时 velocity/orientation 惩罚力度不足以抑制高速接近行为。

## 4. 行为结论
**病态**。策略学会了"高速盘旋在目标附近赚取 progress 奖励，避免接触以延长回合"的 exploit 行为。

**最需要干预的组件**：
1. **goal_approach_progress**（立即）：系数 80.0 创造了错误激励，需降回 10.0 左右并考虑添加递减项（越接近目标 reward 越小）
2. **contact_landing_reward**（次要）：0.3% 激活率说明触发条件过严或量级过小，需提升基础系数或放宽 quality_factor 约束
