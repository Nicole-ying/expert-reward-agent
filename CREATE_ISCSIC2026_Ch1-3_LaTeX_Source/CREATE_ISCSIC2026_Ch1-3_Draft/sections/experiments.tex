\section{Experiments}
\label{sec:experiments}

\subsection{Experimental Design}
LunarLander-v3 is the primary benchmark for baseline comparison and mechanism ablation. BipedalWalker-v3 is used only as an additional validation of the complete CREATE workflow under a different action space and control structure; no baseline or ablation comparison is conducted on that task. Every reward program trains a freshly initialized PPO policy. LunarLander uses $10^6$ environment steps per reward candidate and BipedalWalker uses $5\times10^6$, with four vectorized environments inside each policy-training job. Each condition contains five independent reward-search lineages and at most ten complete reward evaluations.

The policy is optimized with the generated reward, whereas candidate quality is measured only by the untouched environment reward. We define \emph{search fitness} as the mean undiscounted native episodic return over 20 fixed evaluation episodes, and \emph{best search fitness} as the largest search fitness retained in a lineage. After selection, the returned policy is evaluated over 100 episodes whose seeds are not exposed during search; this is reported as \emph{test fitness}. The task thresholds are 200 for LunarLander and 300 for BipedalWalker.

All LunarLander conditions use the same DeepSeek V4 Pro backbone, environment description, reward-generation interface, code checks, and PPO budget. \emph{Single-shot generation} evaluates only the initial reward. \emph{Independent-10} spends ten reward evaluations on unrelated initial candidates. \emph{Stateless iterative revision} repeatedly revises the current reward from basic current-round feedback, but has no tool-organized evidence, persistent intervention memory, cross-round component comparison, or hierarchical semantic edit policy. The two ablations remove either evidence enrichment or hierarchical semantic editing while retaining the remaining CREATE loop. Full prompts, model settings, hyperparameters, and per-seed traces are provided in the supplementary material.

\subsection{Reward Search Under a Matched Training Budget}
Table~\ref{tab:lander_main} separates the value of candidate count, repeated revision, and the complete closed loop. Single-shot generation never solves the task, showing that an initially plausible reward is not reliably learnable. Independent-10 also solves no lineage despite evaluating the same maximum number of reward programs as CREATE. Hence, breadth alone does not recover the information contained in failed policy training.

Stateless revision raises the mean lineage-wise best fitness to $44.0$, but still solves no seed. In three of five lineages, the initial reward is already the best version, and the final revision is worse than the stored best in all five. The process therefore produces non-monotonic rewrites without accumulating reliable progress. CREATE instead solves all five lineages at rounds $8,10,2,4,$ and $3$, requiring 5.4 complete reward evaluations on average to first cross the threshold. Its narrower cross-seed spread further indicates that the gain is not driven by a single favorable initialization.

Fig.~\ref{fig:main_results} should emphasize search behavior rather than repeat table entries. The best-so-far panel shows whether each additional training run contributes useful information; the Success@Budget panel shows how quickly that information becomes a task-solving reward; and the scatter panel exposes instability hidden by mean values. CREATE reaches success rates of $0.2$, $0.4$, $0.6$, $0.8$, and $1.0$ by budgets $2$, $3$, $4$, $8$, and $10$, whereas all three baselines remain at zero. This pattern supports the central claim that repeated LLM calls are insufficient unless training outcomes are converted into persistent state that constrains the next reward action.

\subsection{Mechanism Analysis}
Removing evidence enrichment leaves the editor with native fitness, episode length, termination statistics, and component episode sums, but removes the tool-using evidence organizer, activation rates, magnitude shares, temporal trends, and structured cross-round summaries. This variant solves two seeds but exhibits very high dispersion, including one lineage that remains negative throughout all ten rounds. Basic component values can therefore support occasional repair, but do not reliably distinguish an inactive, weak, saturated, or behaviorally unreachable reward term.

Removing hierarchical semantic editing retains enriched evidence, memory, and the best archive, but allows unconstrained multi-component rewrites. It reaches moderate fitness in several seeds yet solves none, and one lineage collapses to approximately $-5511$ in two consecutive rounds. The failure is not a lack of information: it arises because one training outcome must explain several simultaneous code changes. CREATE instead selects one principal semantic and applies an L1 parameter repair, L2 component refactor, or exceptional L3 redesign, so that the next expensive training run tests a more focused intervention hypothesis.

The seed-0 case illustrates how these mechanisms interact. The auxiliary subagent retrieves and compresses the relevant training and lineage records but does not choose the edit. The reward-editing agent uses that observation to diagnose one principal failure and perform an L2 semantic refactor, after which fitness rises from about $-389$ to 224. A later candidate falls to about $-612$, but the best archive preserves the solved reward. The final figure will report the actual component activation and magnitude changes supporting this transition, so that the discussion traces evidence to diagnosis, action, and outcome rather than inferring mechanism from fitness alone.

\subsection{Additional Validation on Continuous Control}
BipedalWalker-v3 is used to check whether the complete CREATE workflow remains usable when moving from discrete landing control to continuous locomotion. Only full CREATE is evaluated, so this experiment is not used for method ranking.

Table~\ref{tab:bipedal} shows that all five lineages cross the task threshold by the third evaluated reward version. Four initial rewards are already near the threshold and require local refinement, whereas seed~4 provides the more informative stress case: the workflow raises fitness from 103.0 to a task-solving 304.9. The selected policies obtain $310.82\pm5.03$ test fitness over independent evaluation episodes. These results provide limited supporting evidence that the same observation--memory--editing loop remains operational on a continuous-action task. Because no BipedalWalker baselines or ablations were run, we do not claim comparative superiority on this environment or broad task generalization.
