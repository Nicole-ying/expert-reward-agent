硕士论文第三、四章研究规划 · 导师讨论稿

让奖励工程 Agent
从迭代奖励，走向理解训练

第三章研究如何在有限训练预算内形成可执行、可追踪的奖励搜索闭环。第四章研究智能体如何联合奖励代码、PPO 训练曲线、中期策略行为和独立任务评价，判断策略为何学偏，并通过受控实验修复奖励与真实目标之间的错位。

贯穿两章的科学问题
训练反馈如何变成下一次有效的奖励设计决策？

研究对象是奖励设计智能体的分析、规划与修订能力。策略学习器在主实验中固定为 PPO，以便定位奖励机制；最终采用独立任务指标评价。

01 / 总体研究思路

一条闭环，两层研究深度

第三章建立“能迭代”的系统；第四章把训练结果转化为机制判断和可检验的奖励修复。

第三章 · CREATE

任务内奖励搜索

Agent 读取环境说明、奖励代码、历史候选及最终训练反馈；生成奖励程序，调用 PPO 训练和原生评价，在有限候选预算中保留最佳版本。

研究命题：有界工具调用、干预记忆与最佳档案，能否提高有限预算搜索的成功率与稳定性？

第四章 · 训练诊断与奖励修复

读懂一次训练为何成败

Agent 进一步读取代码差分、TensorBoard、PPO 更新状态、中期 checkpoint 与行为数据；提出竞争机制假设，选择能区分原因的实验，再决定修改哪个奖励组件。

研究命题：这种诊断能否预测故障、定位根因，并使新奖励训练出的策略更接近真实任务目标？

两章共用的 Agent loop

1 任务接口目标、观测、动作、终止、合法奖励信号
2 候选奖励程序结构、组件、系数和父子版本差分
3 策略训练固定 PPO 配置，完整保存曲线和 checkpoint
4 独立评价任务得分、成功/终止、位移和行为约束
5 诊断规划现象、机制假设、预测、对照与预算
6 修订记忆执行单组件修改、复验、保留或回退

第三章重点研究 1→2→3→4→6 的有效闭环；第四章重点研究 3→4→5→6 如何形成可信的机制判断。

02 / 第三章研究内容

CREATE：有限预算下的奖励函数闭环迭代

第三章基于已有 CREATE 工作扩写为完整方法章，明确 Agent 能读什么、能调用什么、每轮如何决策。

3.1–3.2 问题与接口

定义搜索对象

任务给定环境、策略算法、预算和独立评价器。Agent 修改奖励程序；每个候选必须通过接口与数值检查，再训练新策略。

3.3 证据与工具

规定 Agent 的可读信息

环境卡、观测动作语义、当前奖励代码、历史版本、组件统计、任务评价、终止与行为摘要。训练奖励和任务评价分开存放。

3.4 搜索决策

生成与有界修订

依据本轮反馈选择局部调权、修改单个机制或重启结构；每次编辑绑定父代、修改理由、训练 seed 和预算。

3.5 执行与档案

完整训练后选优

代码校验 → PPO 训练 → 独立评价 → 记录结果；按任务评价维护 best-so-far，坏编辑不覆盖已验证的好奖励。

3.6–3.7 结果与边界

验证搜索是否可靠

比较有限预算下的成绩、首次达标轮次、跨 seed 波动与计算成本；用 Ant 和困难步行任务说明仅看最终分数的不足。

第三章的贡献边界：Eureka 已使用候选搜索与奖励组件反思，RF-Agent 已研究分支搜索。因此本章要证明 CREATE 这套“工具取证—有界干预—执行留痕—最优档案”协议在相同候选训练预算下的效果，而不把单独的记忆或反思称为首创。
03 / 第三章实验规划

已有结果作为基础，补齐外部比较与独立复训

十轮表示每条搜索谱系的深度。统计单位是独立搜索 seed 和重新训练的策略 seed。

任务研究作用现有基础第三章继续完成的实验
LunarLander-v3验证离散动作任务中工具与记忆闭环是否有效。现有论文整理记录了 10 个配对搜索 seed、最多 10 次候选训练；需要以最终稿和原始日志统一数值。保留已完成的主实验；补充同预算 Text2Reward 一次生成、Eureka 式 2×5/5×2 搜索组织，以及最终奖励的新策略 seed 复训。
BipedalWalker-v3验证连续动作、步态协调与跨任务适用性。现有论文整理记录了 10 条 CREATE 搜索达到目标，但外部同预算对照与选后未见测试尚需补齐。固定 PPO 与每候选步数；补齐外部生成/进化基线、无状态顺序修订、最终奖励多训练 seed 复训。
Ant-v4展示第三章方法在高维运动中的困难边界。已有多条十轮搜索，出现高分峰值、回落和显著跨 seed 差异。只作第三章边界案例与第四章研究动机；主结论依赖第四章的机制实验。

比较、消融和统计读数

外部搜索方法

原生奖励训练作参考；Text2Reward 作单次生成基线；Eureka 的并行选优改为同预算版本；有能力适配时加入 RF-Agent 式树搜索。明确标注“预算适配”，不将其说成原论文完整复现。

CREATE 机制消融

无工具、无记忆、无最佳档案、无编辑边界；另比较 1×10 单谱系与 2×5 多起点，回答深度修订何时优于扩展搜索覆盖。

最终评价

每条搜索报告 best-so-far 曲线、首次达到预设目标的候选编号、选中奖励的独立 PPO 复训成绩、不同训练 seed 方差和总环境交互。

已完成结果与新增实验在正文和图表中分开标注；第三章结论只依据完成复训和对照后的数据。

图中曲线为 TensorBoard rollout/ep_rew_mean 的抽样趋势，三个候选的奖励定义不同；不能用曲线高度比较奖励质量。

代码与最终策略给出的具体线索

第 6 轮：1.5 × 前进速度 × 高度门控 + 姿态奖励 − 横向速度惩罚。最终策略评价时，门控前进项累计约 2578，20/20 回合跑满 1000 步，但原生回报均值约 −37。代码没有显式动作代价；组件日志还把门控乘子误当作可加奖励项。

第 7 轮：只新增 −0.01 × 关节速度平方和。最终评价中新增项累计约 −377，前进项从约 2578 降至 2043；20/20 回合仍跑满，原生回报降至约 −354。

第 8 轮：新结构把前进项压到小于 1，姿态/高度惩罚权重各为 5；训练中 episode 长度降到约 12 步，最终 20/20 终止。其组件字典把实际被减去的惩罚报成正值。

Ant-v4 原生回报 ≈ 健康奖励 + 前进位移 / Δt − 0.5 × ||动作||²；第 6 轮生成奖励 = 1.5 × 观测前进速度 × 高度门控 + 轻姿态奖励 − 横向速度惩罚。

第四章 Agent 必须完成的机制推理

观察 1

训练与任务分离

第 6、7 轮生成奖励不断上涨，原生回报却为负。先判断 PPO 是否确实在优化被提供的奖励，而不是直接说“训练失败”。

观察 2

检查奖励程序

生成奖励强调门控前进，缺少与原生任务相同的动作代价；第 7 轮额外压低关节活动。必须核对信号时序、各项量级与日志符号。

机制假设

PPO 可能学到局部保守行为

PPO 用候选奖励形成优势估计，再通过裁剪目标更新策略；新增关节惩罚可能降低高活动动作的相对优势。第 7 轮策略标准差约 0.994→0.270、clip fraction 约 0.097→0.461，且熵系数为 0；因此怀疑策略逐渐收敛于较低活动的稳定步态。

反证测量

区分三种原因

逐 checkpoint 测位移、前进速度、动作平方代价、关节速度、高度门控、原生回报分项与终止。若位移仍高但动作成本更高，就不是“过度保守”。

受控修改

预测后再编辑

分别测试动作代价对齐、降低关节速度惩罚和修改高度门控；同父奖励、同训练 seed、同预算，一次只动一个机制，再核对预测的轨迹变化。

证据等级：现有记录证明“候选回报上涨与最终原生回报不一致”，并支持第 7 轮新增关节速度惩罚值得检查；它还没有给出中期原生回报、真实位移或动作代价。因此“PPO 学出保守步态”目前是待反证的机制假设，不能写成已完成的归因结论。高 clip fraction 表示更新频繁触及裁剪区，并不能单独证明 PPO 是根因。
05 / 第四章研究内容

机制诊断 Agent：看懂现象、提出假设、验证修改

FARL 已提出“设计—训练—诊断”循环。本章聚焦固定 PPO 下奖励程序的机制归因，并把诊断正确性和修复效果分别量化。

Agent 读取的证据包

  • 程序：环境接口、奖励代码、父子 diff、每项的符号/尺度/门控/饱和。
  • 训练：TensorBoard 的候选回报、长度、KL、clip fraction、entropy/标准差、explained variance、value loss。
  • 中期策略：20/40/60/80/100% checkpoint 的独立任务评价、原生奖励分项、代表轨迹和行为统计。
  • 历史：父代结果、已测试的假设、失败反例和适用条件。

Agent 每轮必须输出的研究记录

  • 现象：哪段曲线、哪项任务指标、哪个行为出现偏差？
  • 机制：至少两个竞争解释，区分奖励错位、探索不足、值函数估计问题和评价波动。
  • 预测：若解释成立，下一 checkpoint 的位移、动作代价、终止率、原生回报应如何变化？
  • 实验：固定什么、只改什么、配对哪些 seed、何时停止。
  • 决策：保留、回退、补证或修订，并把结果写入条件化记忆。
证据包 → 现象定位 → PPO/奖励机制假设 → 可区分的实验 → 单组件修改 → 独立任务复验 → 更新记忆

训练前：代码机制审计

用随机和已有轨迹回放，检查奖励项符号、尺度、边界和组件上报是否与实际加减法一致。输出可能的策略捷径和预期风险。

训练中：代理目标对齐检查

同一 checkpoint 同时计算候选奖励、独立任务指标及行为量。识别“候选分数增加而任务表现下降”的时间点，判断是否继续训练、补测或换奖励。

训练后：归因与修复

把代码编辑和曲线、轨迹变化对应起来；用配对 seed 的单因素实验验证假设，记录反例，防止一次偶然高分变成永久设计规则。

预期方法贡献：把“反思上一轮”具体化为可以盲测的机制诊断和可反驳的干预预测。FARL 的优势是联合搜索观测、算法和训练设置；本章固定这些条件，研究奖励程序与 PPO 学习过程的对齐问题，并检验诊断本身是否可靠。
06 / 环境与难度梯度

借鉴 FARL 的分层任务设计，形成可执行的环境矩阵

FARL 使用 DoorKey、Ant、Door-Open、Adroit Hand Relocate，覆盖导航、运动和操作。本论文按现有接口和固定 PPO 的研究目标选择核心任务。

任务与地位为什么选择要暴露的奖励/学习问题主指标与状态
LunarLander-v3 第三章核心已有 CREATE 多 seed 结果；离散控制，便于说明基本搜索闭环。降落速度、姿态、着陆成功与生存时长的奖励权衡。原生回报、成功率、首次达标轮次；已有结果，补外部对照。
BipedalWalker-v3 第三章核心已有步行任务记录；检验连续动作的奖励迭代。前进、稳定与能耗之间的冲突。原生回报、达到 300 的比例、多 seed 复训；已有结果，补独立测试。
Ant-v4 第四章主任务现有记录显示明显代理错位和跨 seed 失稳；便于对照真实奖励分项。高维步态、门控前进、动作成本与 PPO 探索收缩。原生回报、前向位移、动作代价、终止率、诊断准确率。
BipedalWalkerHardcore-v3 第四章困难迁移本地 4 条完整十轮搜索的最好分数仍约 −52～−18，属于真实未解决记录。跨越障碍需要阶段行为；保守存活可能抑制前进。原生回报、障碍通过率、跌倒位置、早期预测与修复率。
DoorKey 5×5 第四章机制外推借鉴 FARL 的阶段任务，用不同于连续运动的导航检验诊断能否识别“拿钥匙、开门、退出”的停滞位置。阶段奖励可能只优化中间里程碑，未推动完成最终任务。最终通关率及各阶段到达率；需要新增环境适配器。
Door-Open / Adroit Hand Relocate 扩展验证对应 FARL 的操作与高难度压力测试；在前三项主任务完成后再进入。接触、操作阶段、长期稀疏反馈；PPO 可学习性先以原生奖励摸底。开门/搬移成功率；接口与 PPO 原生基线通过后才列为正式实验。
FARL 式预算阶梯：Ant 先以 5k 检查程序能否运行，再以 50k/300k 观察学习方向，只有值得继续或具有对照价值的候选训练到 1M；入选方案再做 5M 长训练。本论文的主效果比较仍固定每候选 1M PPO；另设效率实验测试上述阶梯，所有探针步数计入总预算。
比较边界：FARL 还搜索观测、PPO/TD3/SAC 和训练配置，本论文固定 PPO 与策略观测，因此不把两篇论文的 Ant 数值直接并列排名。
07 / 第四章实验方案

先证明 Agent 看懂训练，再证明它改对奖励

训练配置、评价种子和成功判据在正式比较前锁定；候选生成与训练消耗都计入预算。

实验 A · 数据与诊断题库

把训练过程变成可核对的证据

在 Ant 与 Hardcore 中保存 20/40/60/80/100% checkpoint。每点记录候选回报、原生回报分项、位移/阶段进度、动作/关节代价、终止与 PPO 状态。

利用历史真实失败，加上在相同父奖励中注入的单一故障：符号、量级、门控死区、饱和、常开惩罚、漏掉动作代价。

实验 B · 中期盲测

预测未来而非事后解释

Agent 只看到代码及 20%/40% 以前的数据；隐藏后续 checkpoint 和完整训练结果。输出最终表现区间、故障机制、问题组件、证据、建议干预和置信度。

按完整搜索谱系与奖励家族分训练/测试；相邻代码不跨集合，避免“看过下一轮答案”。

实验 C · 受控修复

检验机制判断是否真实

选 Agent 指出的组件，固定父奖励、PPO 配置和配对训练 seed，一次仅改一个语义单元。先预测曲线/轨迹变化，再训练并复验。

同时保留“原奖励继续训练”“随机合理编辑”“只看最终分数编辑”等对照，比较错误修改率与原生表现增益。

实验 D · 完整搜索

检验最终奖励质量

在 Ant 主任务上，与 Text2Reward、Eureka 式同预算进化、RF-Agent 式树搜索比较；DoorKey/Hardcore 检验跨机制适用范围。

每种迭代方法先用 5 条独立搜索谱系，每条最多 10 次完整 PPO 候选训练；入选奖励再用 5 个新 seed 复训。

两类比较回答两个不同问题

外部方法：找到的奖励是否更好

Text2Reward、Eureka-style、RF-Agent-style 和原生奖励训练为主要对照。统一任务接口、基础模型、有效候选数、PPO 步数与评价集。FARL 作为实验设计参照，若不复现其联合搜索，不写作直接成绩对手。

内部消融：为什么 Agent 会判断

依次比较仅看代码、加入截至当前的 TensorBoard、加入中期原生评价、加入 PPO 机制规则、加入配对验证与条件记忆；盲测各组都看不到该候选未来分数。关键是看诊断正确率和修复率如何变化，而非只看最终分数。

研究问题主要客观指标成功判据
能否提前识别候选奖励会学偏？故障类别 macro-F1、最终原生分数 MAE/区间覆盖率、预警提前步数。中期盲测显著优于仅看代码/最终单点反馈的对照，并保持合理校准。
能否找到造成偏差的奖励组件？可控故障的 top-1/top-3 定位、证据引用正确率、机制区分实验的命中率。定位对应实际注入故障；真实案例须经配对干预支持。
修改后是否更接近任务目标？预测行为兑现率、配对原生回报变化、负迁移率、无效完整训练次数。预测的位移/动作代价/阶段进度发生方向一致变化，独立任务表现改善。
完整奖励搜索是否有效？best-so-far—总环境交互曲线、首次达标预算、最终奖励新 seed 复训均值与方差。在相同预算下与外部搜索方法比较，完整呈现全部 seed 和计算成本。
预算示例（Ant 主比较）：3 种迭代方法 × 5 条搜索谱系 × 10 个候选 × 1M = 150M 训练步；15 个入选奖励 × 5 个新 seed × 1M = 75M 步。诊断故障集、探针、原生奖励参考和其他环境单独记账。若 5 条谱系仍不稳定，优先扩至 10 条独立谱系。选出的代表奖励可在所有方法一致的条件下由 1M 延长到 5M，单列比较后期学习能力和追加成本。
